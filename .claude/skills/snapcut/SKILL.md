# snapcut 라우터

인자: `<이름>` (= `projects/<이름>/`) + 요청 문장. 모든 명령은 저장소 루트에서 `.venv/bin/python -m pipeline ...`.

## 1. 분야와 모드 고르기
요청과 `projects/<이름>/영상소스/`를 보고 아래 표에서 고른 뒤, **어느 모드로 무엇을 만들지 한 줄로 말하고** 시작한다. 애매하면 추천 하나를 말하고 진행한다(묻지 않는다).

| 분야 | 모드 | 언제 | 진행 문서 |
|---|---|---|---|
| ② 기존 영상 편집 | memory-mv | 사진·영상 여러 개 → 음악 맞춘 추억 뮤비 | `modes/memory-mv.md` |
| ② 기존 영상 편집 | longform | 긴 녹화 1개에서 장면을 뽑아 하이라이트 + 자막 + 쇼츠 | `modes/longform.md` |
| ② 기존 영상 편집 | edit | 말하는 영상 1개 전체를 살리며 무음·실수 컷, 자막, 오버레이 | 준비 중 (계획 2) |
| ① 제품 출시·소개 | promo | 제품·서비스 소개, 출시 영상, 홍보 | 준비 중 (계획 3) |
| ③ 짧은 애니메이션 | animation | 설명형 애니메이션, 모션그래픽, 손그림·픽셀 스타일 | 준비 중 (계획 4) |
| ④ 웹사이트 애니메이션 | web | 웹페이지 요소 애니메이션 (결과는 사이트 + 미리보기 영상) | 준비 중 (계획 5) |

영상 1개일 때 요청이 없으면: 10분 이상은 longform, 그 미만은 edit. "준비 중"인 모드가 필요하면 그렇다고 말하고 가장 가까운 준비된 모드를 제안한다.

## 2. brief.json
모드를 정하면 `projects/<이름>/brief.json`을 쓴다(모든 모드 공통 머리말):
```json
{"mode": "memory-mv", "kit": null, "title": "인왕산, 두 번째 산행", "formats": ["youtube"], "music": "QWER - 고민중독 [가사 Lyrics].mp3", "request": "사용자 원문", "effects": []}
```
`mode`는 위 표의 영문 이름. `kit`은 외부 키트를 쓰는 모드에서 `kits.lock`의 이름. 영상소스가 없는 모드(promo, animation, web)는 `projects/<이름>/`만 만든다.

## 3. 렌더 후 점검 (모든 모드)
- 렌더는 사용자가 요청할 때만 한다.
- `pipeline render`는 끝나면 음량 마스터링과 품질 점검을 자동으로 돈다. 키트가 직접 만든 mp4는 `output/`에 두고 `pipeline master <mp4>` → `pipeline check <이름>`을 직접 돌린다.
- 점검이 실패하면 **완성이라고 말하지 않는다.** 실패 항목(시각 포함)을 전하고 고친다.
- 통과하면 `output/check/<파일>/sheet_*.jpg`를 **전부** Read로 보고 아래를 확인한 뒤 완성 경로를 알려 준다:
  - 글씨 잘림·겹침, 안전 영역(릴스·쇼츠는 위아래 UI 자리)
  - 첫 프레임이 검정인지, 누운 영상
  - 화면마다 시선이 갈 곳이 하나인지
  - 퇴장이 등장보다 빠른지, 움직임의 가속 곡선, 등장 순서(LottieFiles 원칙)

## 4. 외부 키트
`kits/`에 `kits.lock`의 커밋으로 받혀 있다(`pipeline kits`로 받기·상태 확인). 키트를 쓰는 모드는 그 키트의 `SKILL.md`를 `kits/<이름>/<경로>`에서 직접 읽고 따른다. 키트 기본값이 유료 API 키를 쓰면 로컬 대체(whisper.cpp, `npx hyperframes tts`)를 쓰고, 대체가 없으면 그 기능을 끈다.

## 규칙
- `영상소스/` 안에는 절대 쓰지 않는다.
- 음악 저작권 판단·경고를 하지 않는다.
- 오류 메시지는 그대로 전하고, 원인이 입력 json이면 고친 뒤 다시 실행한다.
