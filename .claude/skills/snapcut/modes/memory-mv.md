# 추억 뮤비 모드 (memory-mv)

렌더 후 마스터링·점검과 완성 보고는 SKILL.md §3을 따른다.

인자: `<영상명>` (= `projects/<영상명>/`), 선택 `--바로`(확인 없이 렌더까지).
`--바로`는 스킬 수준 옵션이다(CLI 플래그 아님). 기본값: 형식은 릴스·유튜브 둘 다, 음악은 사용자가 말한 곡(없으면 `공용/음악`에서 Claude가 추천한 곡을 묻지 않고 사용), 타이틀·엔딩 문구는 Claude가 작성.
모든 명령은 저장소 루트에서 `.venv/bin/python -m pipeline ...`로 실행한다.

## 1. 준비
`.venv/bin/python -m pipeline prepare <영상명>` — 변환·선별·하이라이트·썸네일 시트. 몇 분 걸릴 수 있으니 Bash `run_in_background`(또는 `timeout` 600000)로 실행하고 끝날 때까지 기다린다. 출력의 제외 목록, 시각 정보 없는 항목 수를 사용자에게 한 줄씩 전한다. 사용자가 흔들린 사진도 원하면("추억이니까 다") `--keep-blur`로 실행한다.

## 2. 고르기
- `.cache/sheets/sheet_*.jpg`를 **전부** Read로 본다. 칸의 `#번호` = `candidates.json`의 인덱스 = selection의 `id`. `V3s`는 영상(길이).
- `.cache/candidates.json`에서 시각(`taken_at`)·종류(`type`: photo/video)를 확인한다.
- 고르는 기준: 사람 표정이 좋은 컷, 장소가 드러나는 풍경, 음식·소품 같은 디테일을 섞는다. 비슷한 구도가 연달아 나오면 하나만. 눈 감은 사진, 초점 나간 사진, 의미 없는 바닥·하늘은 뺀다.
- 넉넉히 골라도 된다 — 자리가 모자라면 plan이 유튜브에서는 이웃한 사진을 2분할 화면으로 필요한 만큼 묶고(릴스는 묶지 않음), 그래도 넘치면 처음·끝을 살려 균등하게 줄인다. 분할이 많아지면 보기 답답하니 유튜브 2분할이 10개 안팎이 되도록 사진 수를 고른다. 영상이 많으면 `in/out`을 1.5~2초로 짧게 잡아 뮤비식으로 넣어야 사진 자리가 남는다.
- 순서는 시간순 유지. 바꿀 이유가 있으면 사용자에게 말한다.

## 3. 음악·문구·형식
- 음악이 정해지지 않았으면 `.venv/bin/python -m pipeline music`으로 `공용/음악/` 목록을 보여주고 분위기에 맞는 곡을 추천한 뒤 사용자에게 고르게 한다. 저작권 판단·경고는 하지 않는다(사용자 몫).
- 형식(릴스/유튜브/둘 다)을 사용자가 말하지 않았으면 묻는다.
- 타이틀·부제·엔딩 문구를 제안한다(예: "제주, 2026 가을" / "2026.09.12–15" / "함께해서 즐거웠어").


## 템플릿 모드 (여행)
친구 여행·수련회·가족 여행 등 여행 영상이면 `공용/템플릿/여행/template.json`(편집 문법: 손글씨 카드, 소리·속도, 오프닝 블러, 구간 마커, 3비트 사진 피날레, 크레딧 형식)을 쓴다. 템플릿에는 사람·문구가 없다 — 여행마다 정한다.
- 먼저 묻는 것: **어떤 여행인지**(누구와·어디·어떤 자리). 그에 맞춰 타이틀·엔딩·크레딧을 제안한다.
  - 예) 친구 "동심지키미 in 가평" / "다음 행선지는 어디?" · 수련회 "2026 청년부 여름 수련회" / "은혜로 가득했던 3일" · 가족 "우리 가족 제주" / "또 같이 가자"
  - 크레딧은 넣을지부터 묻는다. 넣으면 줄은 자유(직함 농담, 조 편성, "엄마/아빠" 등).
- 자주 가는 일행은 `공용/모임/<이름>.json`(git 제외, 실명)에 있다: `{"name", "people": [{"name", "role"}], "credits": [줄...], "examples": {"title", "ending"}}`. 해당되면 읽어서 초안으로 보여 주고 "이번에 온 사람만" 확인한다. 새 일행이면 다음에도 쓸지 묻고 저장한다.
- prepare는 `--keep-blur`.
- selection: `{"template": "여행", "title": "...", "ending": "...", "music": "...", "introVideo": {...}, "outroVideo": {...}, "credits": {"lines": [...], "video": {"id": n, "in": s}}, "items": [...]}` (credits는 넣을 때만)
- items: 오프닝 이동 영상 3개(블러 전환 자동) → 시간순 본편(영상 우선, 사진은 영상 없는 장면만) → `{"at": "브릿지"}` 신나는 영상 → `{"at": "브레이크"}` 잔잔한 장면 → `{"at": "마지막후렴"}` 귀가 영상 → `{"at": "피날레"}` 단체·셀카 사진 20~25장(3비트·멈춘 사진 자동) → (선택) 엔딩 특별 사진.
- plan 출력의 `구간:` 줄을 사용자에게 전하고, `(추정)`이 붙은 구간은 Studio에서 들어 보고 selection 최상위 `"sections": {"마지막후렴": 160.2}`로 고친다 (이름 마커는 그대로 두면 피날레·3비트 사진이 고친 값을 따라간다). `놓을 수 없어 무시한 마커`가 나오면 그 구간의 순서·시각을 확인해 `sections`로 고친다.

## 4. selection.json 작성
`projects/<영상명>/selection.json`:
```json
{
  "title": "제주, 2026 가을",
  "subtitle": "2026.09.12–15",
  "ending": "함께해서 즐거웠어",
  "music": "song.mp3",
  "formats": ["reels", "youtube"],
  "intro": "basic",
  "introVideo": {"id": 12, "in": 0.0},
  "outroVideo": {"id": 40, "in": 1.0},
  "items": [{"id": 0}, {"id": 7, "in": 2.0, "out": 5.5, "liveAudio": true}]
}
```
영상 항목의 `in/out/liveAudio`는 생략하면 하이라이트 제안값을 쓴다. 하이라이트 제안은 결정적 순간(물에 빠짐 등)을 자주 놓치니, 재미있는 영상은 `ffmpeg ... -vf fps=4,tile=5x4`로 프레임 시트를 만들어 순간을 직접 찾아 `in/out`을 잡는다. 옆으로 누워 찍힌 영상(시트에서 사람이 가로로 누움)은 빼지 말고 `"rotate": -90`(또는 90/180)으로 세워 넣는다. 추억 영상에서는 같은 순간이면 사진보다 영상을 우선한다. 웃음·함성처럼 현장 소리를 살릴 장면만 `liveAudio: true`. 현장 소리 구간에 음악을 덜 줄이려면 그 항목에 `"duck": 0.6`(그 구간 음악 볼륨, 기본은 0.3). 줄었다 돌아오는 속도는 `"duckFade": 2.0`(현장 소리 앞뒤로 서서히 줄고 커지는 초, 기본 0.3 — 확 줄어든다는 반응이면 1.5~2). 현장 소리를 살리되 음악을 줄이지 않으려면 그 항목에 `"duck": false`, 프로젝트 전체면 selection 최상위에 `"duck": false`. 모든 영상의 현장 소리를 켜려면("현장감 있게") 최상위에 `"liveAudio": true`(항목별 지정이 우선).
`intro` 템플릿: `basic`(어두운 배경 + 고딕), `handwritten`(배경 영상 위 손글씨, 타이틀을 공백 단위로 대각선 배치 — "동심지키미 in 가평"). `introVideo`/`outroVideo`는 카드 배경 영상(후보 번호, 시작 초부터 3초).

## 5. 타임라인 계산
`.venv/bin/python -m pipeline plan <영상명>` — 형식별 길이·장면 수·뺀 항목 수를 사용자에게 전한다. 처음 카드를 렌더할 때(첫 실행, 문구·템플릿 변경 시)는 몇 분 걸리므로 Bash `run_in_background`(또는 `timeout` 600000)로 실행하고 기다린다.

## 6. 확인 (`--바로`면 건너뜀)
`.venv/bin/python -m pipeline studio <영상명> [--format reels]`을 **백그라운드로** 실행하고 http://localhost:3002 를 알려준다(HyperFrames Studio, 형식 하나씩 — 기본은 첫 형식). 수정 요청("3번째 사진 빼", "후반 빠르게", "타이틀 바꿔")은 selection.json을 고치고 5단계를 다시 실행한 뒤 studio를 다시 실행하고 "새로고침"을 안내한다.
- 미리보기 왼쪽 위에 지금 장면의 파일 이름(영상이면 원본 몇 초)이 뜨고 **Q 키**로 복사된다. 사용자가 붙여 준 `<파일이름> <초>초`는 `candidates.json`의 `file`(`media/<파일이름>.<확장자>`)로 후보 번호를 찾고, 초는 원본 영상 기준이다.
- 사용자가 말하는 시각("1:42")은 Studio 표기 `분:초`다 → 102초. 프레임 단위가 필요하면 이름표의 원본 초나 곡을 들어 onset으로 맞춘다. 유튜브는 곡 시작 = 영상 시작이라 곧 곡 시각이다.
- 음악에 맞춘 연출은 items 사이의 `{"at": 곡 기준 초}` 마커로 한다. 마커 다음 항목은 정확히 그 시각에 시작하고, 앞 구간은 마지막 사진을 늘려 빈틈 없이 잇는다. 정확한 시각은 librosa onset(타악 성분)으로 찾는다.
  - 비트 쪼개짐("빰.빰빰빰"): 타격 시각마다 마커 + `{"id": n, "solo": true}` 한 장씩, 끝 시각에도 마커.
  - 브릿지·후렴·브레이크 같은 구간 시작에 마커를 두고 그 구간 분위기에 맞는 항목(신나는 영상 1.7초씩 / 잔잔한 사진)을 넣는다. 구간이 길면 마지막 사진이 오래 멈추니 항목을 더 넣는다.
  - `"solo": true` 사진은 분할 화면으로 묶이지 않는다("잘린다" 요청).
  - 사진 → 같은 장면 영상으로 "살아 움직이게": 영상에서 사진과 가장 닮은 프레임을 찾아(밝기 정규화 상관, 30fps 단위) 그 초를 `in`으로, 사진은 `{"solo": true, "kenBurns": "zoom-out"}`(원래 크기로 끝나 구도가 맞음), 영상에 `"dissolve": 0.4`. 사진이 영상 프레임 그대로가 아니면(라이브 포토 등) 딱 자르면 튀니 디졸브로 잇는다.
  - 유튜브에서 세로 사진을 2~3장씩 한 화면에 나란히: selection 최상위 `"photoGroup": 3`(이웃한 세로 사진끼리 — 가로 사진은 혼자 크게 보이는 게 낫다는 반응이라 묶지 않음. 가로 사진은 한 장이 한 칸을 써서 자리가 빨리 찬다, 한 화면 = 사진 두 장 몫의 시간). 영상·마커·`solo`·`kenBurns`/`photoBeats`를 지정한 사진(피날레 등)에서 끊긴다. 묶이면 자리가 남으니 사진(풍경 등)을 더 넣고, 한 구간의 마지막 화면이 5초 넘게 멈추는지 확인한다. 따로 보여 줄 사진(마지막 인물 사진 등)은 `"solo": true`.
  - 마지막 영상을 검게 사라지게: 그 항목에 `"fadeOut": 초`(0~3, 원본 기준 "N초부터"면 out − N). 아웃트로 카드는 검은 화면에서 떠오르고, 글씨가 먼저(카드 8초) 사라진 뒤 화면이 9~11초에 어두워진다. 마지막 장면이 엔딩 그림의 원본 사진이면(그림이 그 사진을 그린 것) 검게 사라지지 말고 `"outroDissolve": 1.5`로 사진에서 카드로 서서히 바뀌게 한다(둘 다 16:9라 구도가 맞음). 아웃트로 배경이 단체 사진·그림처럼 사람으로 꽉 차면 최상위 `"outroLayout": "top"`(글씨를 위쪽에), 아래쪽 2/3 지점 한 줄이면 `"low"`.
  - `"dissolve": 초`(0~1)는 그 장면이 앞 장면 위로 서서히 떠오르게 한다. `"blur": 초`(0~1.5)는 가우시안 블러 전환 — 앞 장면이 끝 절반 동안 흐려지고 이 장면이 앞 절반 동안 선명해진다(오프닝 전환 등).
  - 사진 피날레(참고 영상 문법): 마지막 후렴 중간 마디 첫 박에 `{"at": t, "photoSeconds": 1.05}`(172BPM이면 3비트) 마커를 두고, 여행 전체의 단체·셀카 사진 20~25장을 시간순으로 `{"id": n, "kenBurns": "still"}`. 본편은 영상 위주로, 사진은 영상이 없는 장면에만. 유튜브·릴스 모두 분할 화면은 쓰지 않는다.
  - 엔딩 크레딧(유튜브만): selection 최상위 `"credits": {"lines": ["Special 땡스", "운전 OO", ...], "video": {"id": n, "in": s}, "seconds": 12}` — 아웃트로 뒤에 붙고, 음악은 크레딧 전에 페이드아웃, 영상 자체 소리가 나온다. 멤버 이름·역할은 사용자에게 받는다(지어내지 않음). 사진 `"kenBurns"`는 zoom-in / zoom-out / pan-left / pan-right / still(기본 — 확대·이동이 어지럽다는 반응이라 풍경 하이라이트 몇 장에만 zoom-in을 지정하고, 지정한 사진은 분할 화면으로 묶이지 않는다) / scroll-down(4컷처럼 세로로 긴 사진을 확대해 위→아래로 훑음 — 사진 항목에 `"photoBeats": 6`으로 그 사진만 길게) 중 지정.
- 카메라·전환 효과(느낌으로 요청하면 `references/techniques.md`로 고른다). 영상 항목: `"speed": 0.5`(슬로 모션, 0.25~10, 4 = 빨리 감기·타임랩스), `"speed": [1, 0.3]`(스피드 램프 — 장면 동안 1배속→0.3배속), `"freeze": 1.0`(끝 장면 멈춤 초, 0.3~3), `"jcut": 0.5`/`"lcut": 0.5`(현장 소리를 화면보다 먼저/늦게 0.2~2초, liveAudio 영상만, speed와 함께 못 씀). 사진·영상 공통: `"whip": 0.4`(휩 팬 전환 0.2~0.6), `"wipe": 0.6`(와이프 전환 0.3~1.5), `"shake": 0.5`(핸드헬드 흔들림 0~1), `"dutch": 8`(더치 앵글 ±15도). 전환(dissolve·blur·whip·wipe)은 항목당 하나.
- 효과(사용자가 원할 때만, 기본 꺼짐): 최상위 `"effects": {"sfx": true, "beatAccent": true, "filmLook": true}`.
  - `sfx`: 전환마다 휙 + 드롭(마지막 후렴 첫 다운비트 — 영상이 그 전에 끝나면 영상 안의 가장 늦은 후렴)에 라이저·임팩트. claude-motion 키트 합성기로 plan 때 `.cache/music/sfx_<형식>.wav`를 만든다(키트 필요: `pipeline kits`).
  - `beatAccent`: 드롭부터 2마디마다 흰 플래시(최대 8번). 사진 줌·펀치는 넣지 않는다(취향 기록).
  - `filmLook`: 옅은 필름 노이즈 + 비네트.
  - 사진 항목 `"behindTitle": "인왕산"`(1~16자): 사진 → 큰 글자 → 사람만 오려낸 사진 순으로 겹쳐 글자가 사람 뒤로 지나간다. 하늘이 위에 있고 사람 머리가 화면 위쪽 1/3쯤에 있는 가로 사진이 잘 맞는다. 렌더·미리보기 때 HF `remove-background`로 오려낸다(첫 실행에 모델 176MB, 키 없음). 그 사진은 분할 화면으로 묶이지 않는다.
- 컷은 마디에 맞춘다: 4/4 곡에서 3박마다 바꾸면 마디 시작·중간을 번갈아 밟아 어긋나 들린다. BPM이 절반으로 잡힌 곡(빠른 밴드곡이 80~95로 나옴)은 1비트=반 마디이니 사진 4비트(2마디)·후렴 2비트(1마디), 영상 길이도 짝수 비트로. 구간 시작 마커에 `"photoBeats"`, 인트로 카드 끝이 홀수 비트면 첫 마디 첫 박에 `{"at": t}`.
- "빠르게/느리게"는 selection.json의 `"photoSeconds": {"youtube": 2.5, "reels": 1.2}`(사진 한 장면 목표 초, 기본 유튜브 2.0·릴스 1.0, 비트에 맞춰 반올림)와 영상 `in/out` 길이로 반영한다. 느리게 하면 자리가 줄어 분할 화면이 늘고, 그래도 넘치면 영상 개수를 줄인다.

## 7. 렌더
사용자가 렌더를 요청하면 `.venv/bin/python -m pipeline render <영상명> --formats reels,youtube`(요청한 형식만). 몇 분 걸리므로 Bash `run_in_background`(또는 `timeout` 600000)로 실행하고 끝날 때까지 기다린다. 완성 경로를 알려준다.

## 규칙
- prepare를 다시 실행하면 후보 번호가 바뀔 수 있다 — selection.json의 items를 새 시트 기준으로 다시 작성한다.
- `영상소스/` 안에는 절대 쓰지 않는다.
- 오류 메시지는 그대로 전하고, 원인이 selection.json이면 고친 뒤 다시 실행한다.
